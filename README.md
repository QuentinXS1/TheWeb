# theWeb

One map that makes civic life legible. theWeb is a single place where anyone
can look at a map — their neighborhood, their state, the world — and see who represents
them, how those people got there, and what's happening around them.

This is the clean public source release of theWeb. It intentionally starts with
no prior private-repository history, runtime API keys, or redistributed runtime
data snapshots. See [the data folder](data/README.md) for how to build or add
local data before running the full application.

Public repo: `QuentinXS1/theWeb` · bundle ID: `com.thecommunityhub.app`

> New here? Read **VISION.md** for the project’s purpose and `data/README.md`
> for local data and configuration guidance.

## Project overview

theWeb combines civic, geographic, and public-interest information into an
interactive map experience. The repository includes the application source,
data-building utilities, documentation, and local-development resources.

The public release is designed for contributors to explore, run locally, and
help improve the project. Operational deployment details, private release
configuration, and credential-management procedures are intentionally kept out
of this repository.

## Run it locally

Install the project’s documented dependencies, run `node scripts/preview-server.mjs`,
and open the local URL it provides. The full experience also requires locally built
data files; see [`data/README.md`](data/README.md) before starting.

## Repo structure

| Path | What it is |
|---|---|
| `CandidateMapper.html` | Primary application experience and interface. |
| `data/` | JSON the app reads at runtime: `news.json`, `world_poi.json`, `hospitals.json`, `transit.json`, `theaters.json`, `congress_meta.json`, etc. Regenerated by the builders. |
| `scripts/preview-server.mjs` | Lightweight local server for opening the application source. |

## Data pipeline

The full application is data-driven. This slim public release keeps the
application source and local preview server, but does not bundle runtime data
snapshots or data-collection tooling.

Add locally sourced data only when you have reviewed the applicable source terms
and are authorized to use it.

## Notes for contributors

- **Smoke-test before pushing.** Start the local preview, exercise the area you
  changed, and address any visible error before committing.
- **Secrets never get committed.** Use local configuration and keep credentials
  out of every commit.
- Treat generated datasets as build artifacts; regenerate them from documented
  sources rather than hand-editing them.
